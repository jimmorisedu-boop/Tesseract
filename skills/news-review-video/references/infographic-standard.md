# Инфографика: графики, карты, схемы, цифры

Дополнение к [графике кодом](graphics-pipeline.md). Там — как рисовать и как композитить,
здесь — почему инфографика выходит плохой и что с этим делать.

Инфографика в наших выпусках — это **полноэкранный инсерт** (не альфа-оверлей), обычно 4–8 с,
врезается отдельным кадром и живёт по тем же нормам темпа, что и остальной материал.

## 1. Диагноз: откуда берётся «плохо»

Восемь причин, по которым инфографика читается как дешёвая. Проверяй себя по списку.

1. **График собран руками** из `div` и `<rect>`: нет нормальной сетки, осей, подписей значений
   и иерархии. Типографика случайная, цифры висят без единиц.
2. **Данные-заглушки.** «45 %», «в 3 раза», «+230 %» — круглые, ниоткуда, без источника.
   Выдуманная метрика — это не стилистическая мелочь, а выдуманный факт.
3. **Много мыслей в одном кадре.** Заголовок + подзаголовок + легенда + две метрики + подписи
   осей + сноска. Читатель не знает, куда смотреть.
4. **Дефолтная палитра.** Синий «фреймворк» (`#3B82F6` / `#2563EB` / `#1D4ED8`) или ровный
   серый с нулевой насыщенностью — самый узнаваемый признак шаблона. Как и бежево-кремовый фон,
   неоновое свечение, фиолетово-синие градиенты и «стекло».
5. **Легенда вместо прямых подписей.** Нужно, чтобы подпись стояла у самой линии или столбца,
   а не в углу с цветным квадратиком.
6. **Значения без единиц и контекста.** Ряд «18 24 12 31» под «Пн–Чт» читается как что угодно.
   Всегда: число + единица + что это.
7. **Движение не привязано к данным.** Всё появляется одновременно, а цифра меняется через
   секунду после того, как столбец вырос. Движение должно быть следствием данных.
8. **Блок взят из реестра как есть.** У него свои шрифты, свой фон, свой английский копирайт —
   и выпуск превращается в лоскутное одеяло из чужих стилей.

## 2. Правило №1: сначала реестр, потом руки

Руками график не собираем. В реестре HyperFrames около 400 элементов, из них по данным —
несколько десятков. Поиск и установка:

```powershell
npx --yes hyperframes catalog chart --json          # поиск
npx --yes hyperframes catalog data --type=block      # только блоки
npx --yes hyperframes add data-chart --dir .         # установка в проект
```

`add` кладёт файл в `compositions/` и печатает сниппет для вставки в корневую композицию:

```html
<div data-composition-id="data-chart" data-composition-src="compositions/data-chart.html"
     data-duration="15" data-width="1920" data-height="1080"></div>
```

**Проверенная шпаргалка** (имена найдены в реестре 0.8.145):

| Задача | Блоки и компоненты |
|---|---|
| График столбцы + линия, «как в NYT» | `data-chart` (15 с, 1920×1080), `chart-story`, `mk-line-graph` |
| Динамика, рост, падение | `animated-bar-chart`, `bar-chart-race`, `decline-chart` |
| Одна большая цифра | `count-up`, `number-wheel`, `mk-progress-stat`, `mk-usage-arc`, `conic-progress-ring` |
| Карта: мир, страны, регионы | `world-map`, `us-map`, `us-map-bubble`, `us-map-flow`, `us-map-hex`, `spain-map` |
| Карта-акцент, перелёт, «закрыли» | `nyc-paris-flight`, `north-korea-locked-down` |
| Схема, дерево решений, связи | `flowchart`, `flowchart-vertical`, `hw-pipeline`, `whiteboard-ink` |
| Сравнение «до / после» | `comparison-split`, `before-after-wipe` |
| Список пунктов, спеки, статусы | `mk-specs-list`, `grid-card-assemble`, `state-chip-rail` |
| Хронология по битам | `beat-timeline` |
| Плашка новостного типа | `lower-third-bild` |
| Код и диффы | `code-diff`, `code-scroll`, `code-highlight` |
| Скриншот поста, отзыв, рейтинг | `x-post`, `yt-comment-card`, `testimonial-card`, `star-rating-fill` |

Если под задачу нашёлся блок — бери блок и правь данные. Если нет — собери композицию сам по
[графике кодом](graphics-pipeline.md), но не «на глаз»: сетка, оси, подписи значений и источник
обязательны.

## 3. Блок — это каркас, а не финальный вид

Реестровые блоки несут собственные шрифты, палитру и английский текст. Перед врезкой в выпуск
привести блок к нашим токенам:

- **шрифт** — одна гарнитура выпуска, без засечек и курсива (в `data-chart` по умолчанию
  стоит `Libre Baskerville` с засечками и фон `#faf9f6` — и то и другое меняем);
- **палитра** — один акцент выпуска, фон под материал (тёмный или светлый, но не бежевый);
- **текст** — заголовок, подзаголовок, подписи и «Source:» перевести на русский, единицы
  и подписи осей — по-русски;
- **данные** — заменить массивы значений на реальные из ledger;
- **размер** — блоки рассчитаны на 1920×1080; для вертикали менять `data-resolution`, размеры
  и позиции, а не растягивать.

## 4. Контент: что должно быть на экране

- **Одна мысль на кадр.** Один график, одна метрика, один вывод.
- **Заголовок-утверждение**, а не название метрики: «Долг вырос втрое», а не «Динамика долга».
  Заголовок — самое крупное, что есть в кадре.
- **Прямые подписи** у линий и столбцов вместо легенды; значение каждой метки — с единицей.
- **Источник на экране** мелким кеглем внизу: издание, дата. Он же — строка в `assets/sources.json`.
- **Реальные числа из ledger.** Никаких выдуманных метрик, «примерных» процентов и круглых
  значений «для красоты». Нет источника — нет числа.
- **Числа согласованы между собой**: сумма частей равна целому, проценты сходятся, даты попадают
  в день недели, подписи остаются верными и после движения. Одно число не появляется в кадре
  дважды.
- **Единицы и период** в подзаголовке: «янв–июн 2026, млрд ₽».

## 5. Форма: типографика, цвет, композиция

- Одна гарнитура и один набор токенов на весь выпуск; **цифры табличные** (tabular figures),
  чтобы счётчик не дёргался по ширине.
- Размеры: утверждение 88–128 px, второстепенное 44–56 px, читаемый интерфейс ≥22 px после
  масштаба камеры. Акцент — размером и движением, не курсивом.
- Акцент один и осмысленный: ≤8 % пикселей, вне момента «заливки». Один цвет = одно значение.
- Поля: ≥96 px по бокам, ≥64 px сверху и снизу, ≥24 px запаса на пике движения.
- Один фокус на кадр. Не «текст слева, карточка справа» и не карточка, парящая в пустоте.
- Запрещено (см. [графику кодом](graphics-pipeline.md) §6): оранжевый, янтарный, бежевый,
  кремовый, песочный; неон, свечение, ореол; фиолетовый, индиго, фиолетово-синие градиенты;
  «стекло»; эмодзи и стоковые иконки; частицы и конфетти.
- Сетка и оси — приглушённые, вторичные. Подпись оси обязательна, если по цифрам нельзя
  однозначно понять, что это.

## 6. Движение по данным

Движение показывает, как данные устроены, а не «оживляет» картинку:

- столбцы растут снизу вверх со стаггером 8–12 кадров, подпись значения приходит вместе со
  столбцом, а не после;
- линия прочерчивается слева направо, точка едет по фронту прорисовки;
- счётчик считается **в момент действия** и останавливается на финальном значении с выдержкой
  ≥0,8 с; цифра не меняется через секунду после того, как причина случилась;
- акцент вспыхивает на одной — главной — точке данных, остальное остаётся вторичным;
- сетка, оси и подписи осей стоят неподвижно: движется только то, что несёт данные;
- всё остальное — по нормам §5 [графики кодом](graphics-pipeline.md): `expo.out` на появлении,
  уход короче входа на треть, без перелёта, холд дрейфует, а не замирает.

## 7. Приёмка инфографики

Кроме общих проверок из [чек-листа](qc-checklist.md):

- [ ] `npx hyperframes check` — 0 ошибок, контраст WCAG AA;
- [ ] `python scripts/graphics_qc.py <кадр.png>` — палитра, доля акцента (норма ≤ 8 %),
      контраст к фону, запрещённые цвета; скрипт сохраняет копию кадра в 480 px;
- [ ] **тест 480 px**: на уменьшенной копии цифры и подписи читаются, иерархия видна;
- [ ] **тест незнакомца**: по одному кадру понятно, что за метрика, в каких единицах, за какой
      период и откуда данные;
- [ ] числа сверены с ledger и между собой (суммы, проценты, даты и дни недели);
- [ ] источник виден на экране и совпадает с записью в `assets/sources.json`;
- [ ] подписи значений и осей на месте, единицы указаны, легенды-«квадратика в углу» нет;
- [ ] блок из реестра переведён на наши шрифт, палитру и русский текст;
- [ ] нет бандинга на градиентах, нет дрожания текста, нет «духов» на движении;
- [ ] график не перекрывает лицо в кадре и не спорит с титрами/плашками.

### Ловушка `hyperframes check` на SVG

Проверка контраста в CLI меряет DOM и на **SVG-подписях внутри под-композиции** может ругаться
ложно: измеренное значение не меняется при смене цвета текста. Проверено на блоке `data-chart` —
`3.43:1` держалось и при `#a8a29e`, и при почти белом `#f5f5f4`, а подсказка чекера предлагала
сделать текст темнее, что на тёмной сцене только ухудшило бы читаемость.

Что делать:

1. не гнаться за подсказкой чекера, а померить самому — `scripts/graphics_qc.py` считает
   контраст по пикселям кадра (доминирующий «чернильный» цвет против доминирующего фона);
2. для графических объектов (столбцы, области, карты) норма — 3:1 по WCAG 1.4.11, для текста —
   4,5:1; скрипт разделяет их по доле пикселей;
3. ложное срабатывание на SVG в под-композиции — не повод менять цвета, но и не повод его
   игнорировать: сверься с реальным кадром и напиши в отчёте, что проверил вручную.

Скрипт меряет только палитру, контраст и запрещённые цвета. «Выглядит плохо» он не поймает:
одна мысль на кадр, прямые подписи, шрифт и палитра — это решения, а не метрики. Их проверяют
тестом незнакомца и глазами по контактному листу.

## 8. Частые ошибки → как чинить

| Ошибка | Как чинить |
|---|---|
| График из `div` руками, кривые пропорции | взять `data-chart` / `chart-story` / `mk-line-graph` из реестра |
| Выдуманные числа «для наглядности» | только числа из ledger; нет источника — метрику не показываем |
| Легенда в углу | прямые подписи у линий и столбцов, легенду убрать |
| Числа без единиц | единица и период в подзаголовке, единица в подписи значения |
| Пять метрик в одном кадре | одна мысль: один график, один вывод |
| Дефолтная синька/серый, бежевый фон | палитра выпуска: один акцент, фон под материал |
| Всё появляется одновременно | стаггер 8–12 кадров по данным, счётчик в момент действия |
| Блок из реестра как есть | перевести шрифт, палитру и текст на наши |
| Нечитаемо на телефоне | тест 480 px; крупнее кегль, меньше элементов, короче подписи |
| Счётчик «догоняет» картинку | цифра меняется в кадр причины, а не через секунду |

## 9. Что сдавать вместе с графикой

- исходник композиции `graphics/<блок>/` (включая файлы, поставленные из реестра);
- рендер: полноэкранный MP4 для инсерта либо MOV с альфой, если графика лежит поверх футажа;
- контактный лист (в том числе уменьшение до 480 px для проверки читаемости);
- запись в `assets/sources.json` на каждое число: источник данных, издание, дата, ссылка;
- строку в отчёте о темпе: где врезка стоит, сколько длится, что она доказывает.
